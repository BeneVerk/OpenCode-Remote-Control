## Containers

| Container | Responsibility | Tech |
| --- | --- | --- |
| **Aggregator Worker** (apex) | dashboard, registry API (`/api/machines`, `/api/sessions`, `/api/notifications`), notification hub, agent endpoints (`/register`, `/_control`) | Cloudflare Worker (`@beneverk/opencode-remote-fleet-worker`) |
| **Wildcard Proxy** | transparent per-machine proxy (`<machine>.opencode.beneverk.com`) — HTTP, WS, SSE | same Worker, host-routed; `ProxyMode` adapter (subdomain default, subpath-convertor fallback) |
| **SessionRelay DO** | per-session presence, acks, alarm-driven offline | Cloudflare Durable Object (Hibernation WS) |
| **D1** | authoritative registry: `machines`, `sessions`, `notifications` | Cloudflare D1 (SQLite) |
| **KV** | edge-cached `machine → backend` for the proxy | Cloudflare KV (optional index) |
| **Dashboard SPA** | the aggregator UI (grouped machines + sessions + notifications) | static HTML/CSS/JS (designed in `design/dashboard/`) |
| **fleet-agent** | per-machine: starts opencode + cloudflared, registers, keeps control WSS, forwards opencode events | PowerShell now (`@beneverk/opencode-remote-fleet-agent`), cross-platform TS later |

## Self-hosted variant (deferred — P5)

The aggregator core (registry, routing, notifications, dashboard) is runtime-agnostic
behind adapter interfaces (`Storage`, `Realtime`, `AuthProvider`, `Edge`). The
self-hosted target is a **Deno single-binary server** that reuses the dashboard
and points at a local SQLite — see [deployment topologies](./deployment/).
