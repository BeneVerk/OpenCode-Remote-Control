## Why this shape

- The **agent** is the only thing that can see opencode's local `/event` stream,
  so it owns event collection and forwards only notify-worthy events (keeps the
  aggregator dumb + the machine authoritative).
- The **aggregator** is the fan-out point: it stores notifications (history) and
  pushes to every connected dashboard.
- The **browser** turns the push into a native Web Notification, so the user gets
  notified even if the tab is in the background (with permission).
- The **deep-link** uses the same `/<machine>/<session>` → subdomain redirect as
  a normal session open (see [data flows](./data-flows/)).

## Notify-worthy events (initial set)

To be validated against opencode's event stream at integration time:

- session status → `waiting_for_permission` (a tool needs approval)
- session status → `idle` after `busy` (finished / awaiting input)

These map directly to opencode's documented `/session/:id/permissions/:permissionID`
flow and session status field.
