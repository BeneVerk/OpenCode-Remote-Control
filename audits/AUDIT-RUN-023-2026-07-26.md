## 2. Findings (sorted by severity)

### F1 — Stored XSS in dashboard via attacker-controlled session fields  · **S1** · Conf 0.90
- **Stage/Module:** B1/B4 + A · **Location:** `worker/public/app.js:21-30` (rendered via `innerHTML` at `app.js:16-17`), sourced from `/api/sessions` (`index.ts:8-13`, public).
- **Evidence:** `app.js:26` — `` `<span class="title">${s.title || s.id}</span>` `` interpolated into a template string assigned to `innerHTML`. `s.title`, `s.id`, `s.machine` are taken verbatim from any registered session (`relay.ts:30-34` stores `body.title`/`body.sessionId` with no sanitization).
- **Description:** `/register` is unauthenticated (F2); any caller can register a session with `title = "<img src=x onerror=alert(document.cookie)>"`. The dashboard fetches `/api/sessions` and renders the title into the DOM via `innerHTML` → the payload executes in **every** dashboard viewer's browser. Pre-Access this is anonymous stored XSS; once Cloudflare Access is enabled (Phase 3), it becomes **authenticated-user XSS** (session/cookie theft, action-as-the-user).
- **Category:** Injection (XSS). **Impact:** High (code exec in viewer browser). **Likelihood:** High (open registration + public list). **CVSS (est.):** 7.5 (AV:N/AC:L/PR:N/UI:R/S:C/C:H/I:L/A:N).
- **Verification (skeptic):** attempt to refute — does CF or the browser sanitize? No `DOMPurify`, no escaping, `Content-Type` of `/api/sessions` is JSON (sanitization happens at render, which is the defect). Refutation **fails** — finding survives.
- **Status:** Open. **Tags:** DECISION-REQUIRED (fix approach). **→ R1**

### F2 — No authentication / access control on a live, public platform  · **S1** · Conf 0.95
- **Stage/Module:** A + Q · **Location:** `worker/src/index.ts` (entire fetch handler — no identity check anywhere); deployment live at `https://opencode.beneverk.com`.
- **Evidence:** `index.ts` has no read of `cf-access-jwt-assertion`, no auth middleware; `relay.ts:27` `/register`, `relay.ts:44` WS upgrade, `relay.ts:62-77` proxy all execute without identity checks. AGENTS.md "Auth = Cloudflare Access" is **deferred (Phase 3)** yet Phase 0+1 is deployed and reachable.
- **Description:** The platform is live on the public internet with **zero** auth: anyone can register sessions, enumerate/read all sessions (`/api/sessions`), open any session's WS, and drive the proxy. This is the enabling defect for F1, F3, F4, F10.
- **Category:** Broken Authentication / Broken Access Control. **Basis:** OWASP API2:2023, A01:2021. **Impact:** High. **Likelihood:** High (URL is known/public).
- **Verification (skeptic):** refute? — is the URL secret/unguessable? No (`opencode.beneverk.com` is in the repo, docs, and CF dashboard). Survives.
- **Status:** Open. **Tags:** DECISION-REQUIRED (Access enforcement date). **→ R2**

### F3 — Open proxy via attacker-controlled `backend` (SSRF class)  · **S2** · Conf 0.88
- **Stage/Module:** A · **Location:** `relay.ts:32` (`backend: body.backend`), `relay.ts:65-71` (`fetch(meta.backend + …)`); `index.ts:17-35` (open `/register`).
- **Evidence:** `relay.ts:65` `const target = meta.backend + url.pathname + url.search;` then `relay.ts:66` `const resp = await fetch(target, …)`. `backend` is taken from the unauthenticated registration body.
- **Description:** Anyone registers a session with `backend = https://<any-public-url>`; then `GET /<x>/session/<y>/<path>` fetches it **through the Worker** and returns the response → anonymous open proxy to the public internet (abuse, anonymized attacks on third parties, response exfiltration). **Mitigation found (Stage R):** Cloudflare blocks `fetch()` to RFC1918/link-local (incl. `169.254.169.254`) unless a VPC Network binding is configured — our worker has none, so **internal-infra SSRF is blocked**. The public open-proxy remains. *Caveat:* if a future change adds a `vpc_networks` binding, internal SSRF opens up — backend validation is still required (defense in depth).
- **Category:** SSRF / Unvalidated redirect-target. **Basis:** OWASP A10:2021 (SSRF), API8:2023. **Impact:** Medium-High. **Likelihood:** High.
- **Verification (skeptic):** refute via "blocked by CF"? — only the private-IP vector; public open-proxy survives.
- **Status:** Open. **→ R3**

### F4 — Unbounded resource consumption (no rate-limit, no retention)  · **S2** · Conf 0.85
- **Stage/Module:** F + J · **Location:** `index.ts:17` (no rate-limit), `relay.ts:38`/`141-152` (INSERT/UPSERT, never DELETE), `schema.sql` (no retention), `relay.ts:39` alarm only flips status.
- **Evidence:** no `CF-RateLimit`/counter; `relay.ts:144` `INSERT INTO sessions … ON CONFLICT(id) DO UPDATE` — rows accumulate forever; `alarm()` (`relay.ts:124-139`) never deletes.
- **Description:** An unauthenticated attacker can register millions of distinct `sessionId`s → unbounded D1 row growth + Durable Object creation. Free-tier D1 (5 GB, 100 K writes/day) and DO instance limits are trivially exhausted. No cleanup/reaper job.
- **Category:** Unrestricted Resource Consumption. **Basis:** OWASP API4:2023. **Impact:** High (DoS/quota exhaustion). **Likelihood:** High.
- **Verification (skeptic):** refute via "D1 unique-id constraint"? — no constraint caps count; only `id` is PK. Survives.
- **Status:** Open. **→ R4**

### F5 — Zero automated tests  · **S2** · Conf 0.92
- **Stage/Module:** L · **Location:** repo-wide — `worker/package.json` has no `test` script; no `*.test.ts`, no `spec/`, no CI.
- **Evidence:** `package.json` `scripts` = `{dev, deploy, typecheck}` only.
- **Description:** A platform that proxies AI-agent sessions and writes a registry has no unit/integration/E2E tests and no CI gate. Regressions (e.g., the alarm/presence fix `6ecaa09`, the `/register` routing) are caught only by ad-hoc curl. This is a launch-readiness defect for any non-trivial system.
- **Category:** Test coverage. **Basis:** ISO/IEC/IEEE 29148 (verifiable requirements); test pyramid. **Impact:** Medium (undetected regressions). **Likelihood:** High (any change).
- **Verification (skeptic):** refute? — none; absence is verifiable. Survives.
- **Status:** Open. **→ R5**

### F6 — Unsalted fast password hashing  · **S3** · Conf 0.90
- **Stage/Module:** A · **Location:** `relay.ts:154-158`.
- **Evidence:** `relay.ts:156` `const hash = await crypto.subtle.digest("SHA-256", data);` — single unsalted SHA-256 over the password.
- **Description:** Optional session passwords are stored as unsalted SHA-256 → rainbow-table / identical-password recovery. Web Crypto lacks bcrypt/argon2 but supports PBKDF2 (the correct primitive here).
- **Category:** Cryptographic failure. **Basis:** OWASP ASVS V2.4 (salted, slow); A02:2021. **Impact:** Medium. **Likelihood:** Medium (only if password set + D1/DO dump obtained).
- **Status:** Open. **→ R6**

### F7 — Cloudflared tunnel token passed on the process command line  · **S3** · Conf 0.85
- **Stage/Module:** A + S · **Location:** `agent/start-opencode.ps1:92-94`.
- **Evidence:** `-ArgumentList @("tunnel", "--no-autoupdate", "run", "--token", $tunnelToken)` — the secret appears in the process command line, visible to any local user via Task Manager / `Get-Process` / `wmic`.
- **Description:** Long-lived tunnel credentials are exposed to all local principals. Multi-user machines and shoulder-surfing/screen-share make this worse.
- **Category:** Secrets management. **Basis:** NIST SSDF SP 800-218 (Protect); A02:2021. **Impact:** Medium. **Likelihood:** Medium.
- **Status:** Open. **→ R7**

### F8 — No observability (logging / metrics / audit trail)  · **S3** · Conf 0.85

- **Evidence:** no structured log on register/proxy/access; no metrics; no trace; no audit record of who registered/accessed what.
- **Description:** Cannot detect F1/F3/F4 abuse in production, cannot debug proxy failures, no SLO/alerting. For a session-relay this is operationally blocking.
- **Category:** Observability. **Basis:** Module T (OpenTelemetry; SLO-based alerting). **Impact:** Medium. **Likelihood:** High.
- **Status:** Open. **→ R8**

### F9 — cloudflared startup is assumed, not verified  · **S3** · Conf 0.80
- **Stage/Module:** F · **Location:** `agent/start-opencode.ps1:95`.
- **Evidence:** `Start-Sleep -Seconds 3  # let cloudflared connect` — then proceeds to register unconditionally.
- **Description:** If cloudflared fails (bad token, port conflict, network), the agent registers a session with a dead backend; the dashboard shows it "online" until the alarm, and the browser gets a broken proxy. No health check / retry before register.
- **Category:** Reliability (startup). **Basis:** FMEA. **Impact:** Medium. **Likelihood:** Medium.
- **Status:** Open. **→ R9**

### F10 — WebSocket upgrades have no Origin/auth check  · **S3** · Conf 0.78
- **Stage/Module:** A · **Location:** `relay.ts:44-48`.
- **Evidence:** `relay.ts:48` `this.ctx.acceptWebSocket(server, [role]);` — accepts any upgrade with no `Origin` validation and no identity check (role taken from a query param an attacker can set).
- **Description:** Cross-Site WebSocket Hijacking: a malicious page can open a WS to a known session URL in a victim's browser and inject/receive relayed traffic. Compounds with F2. Spec §11 explicitly flagged "confirm WS upgrades pass through Access" — unresolved.
- **Category:** WS auth/CSWSH. **Basis:** OWASP CSWSH guidance; API2:2023. **Impact:** Medium. **Likelihood:** Medium (needs known URL).
- **Status:** Open. **→ R10**

### F11 — No request body-size limits  · **S3** · Conf 0.75
- **Stage/Module:** A/F · **Location:** `index.ts:18` (`await request.text()` buffers full body), `relay.ts:69` (`body: request.body` forwarded).
- **Evidence:** no `Content-Length` cap; `/register` buffers the entire body into a string; the proxy streams arbitrary bodies.
- **Description:** Memory/DoS amplification via large registration or proxy bodies.
- **Category:** Resource consumption. **Basis:** OWASP API4:2023. **Impact:** Medium. **Likelihood:** Medium.
- **Status:** Open. **→ R11**

## 8. Overall conclusion (against objectives, Reasonable assurance)

The Phase 0+1 platform is **functionally complete and correctly deployed** (register → DO → D1 → dashboard → alarm-driven presence all verified live), and the toolchain is green (`tsc` 0 errors, `wrangler deploy` clean, version-controlled, propagated). **However, it is NOT launch-ready as currently exposed.** Two S1 defects — **F2 (no auth on a live public origin)** and **F1 (stored XSS)** — make the deployed endpoint unsafe for any real use until **R1 + R2** land; they are compounded by F3/F4 (abuse). The cluster collapses to one root cause: **edge auth (Cloudflare Access) was planned for Phase 3 but the platform is already public.**
